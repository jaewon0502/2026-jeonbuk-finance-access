# 데이터 설명서

현재 보고서·대시보드의 분석 접점은 1,347곳, 경로 대상은 54곳, 기본 방문 대상은 50곳이다.
입력과 결과의 기준일을 구분하며, 8월 제출 자료를 현재 결과로 사용하지 않는다.

## 1. 현재 분석 입력과 결과

모든 경로는 저장소 루트 기준이다. CSV는 UTF-8(일부 BOM 포함), JSON은 UTF-8이다.
Python에서 CSV를 읽을 때 `encoding="utf-8-sig"`를 사용하면 두 형식을 함께 처리할 수 있다.

| 파일 | 규모 | 용도 |
|---|---:|---|
| `analysis/theory_validation/spatial/route_inputs/outlets_validated.csv` | 1,385행 | 원래 접점과 공식 목록 추가 접점. `finance_open=Y`이며 좌표가 있는 분석 접점은 1,347행 |
| `analysis/theory_validation/spatial/route_inputs/access_road.csv` | 243행 | 행정동 대표점별 거리·품질·경로 대상 판정 |
| `analysis/theory_validation/spatial/route_inputs/venues_jeonbuk.csv` | 6,856행 | 좌표화된 경로당. 후보 선별 전 목록이며 실제 사용승인은 미확인 |
| `analysis/theory_validation/spatial/route_inputs/jeonbuk_route_scenario.json` | JSON | 시군별 후보·출발점·방향별 거리/시간 행렬·제약 |
| `analysis/theory_validation/comparison/final_expanded_input/comparison_summary.csv` | 21행 | 방법·방문 상한·배정 방식별 비교 결과 |
| `analysis/theory_validation/comparison/final_expanded_input/comparison_results.json` | JSON | 비교별 실제 선택 대상·경로·제약 검사·실행 정보 |
| `analysis/feedback_validation/sensitivity_reader_summary.csv` | CSV | 금융업무 표시 유무에 따른 세 가지 시나리오 |

접점·도로망 분석 기준일은 2026-10-12이고 공통 도로망은 2026-10-11 자료다.
지점 업무 표시 확인은 2026-10-13 기록이다. 각 원천의 기준일·조회일이 모두 같지는 않다.

## 2. 주요 컬럼과 단위

### 접근성: access_road.csv

| 컬럼 | 의미·단위 |
|---|---|
| `code`, `sigungu`, `dong` | 행정동 코드·시군·읍면동명. 코드는 문자열로 취급 |
| `lat`, `lon` | 대표점 위도·경도(WGS84, 도) |
| `pop_total`, `pop_65plus` | 총인구·65세 이상 인구(명) |
| `ratio_65plus` | 65세 이상 인구 비율(%) |
| `nearest_km`, `road_km` | 직선거리·도로망 기반 거리(km) |
| `network_km`, `admin_snap_km`, `outlet_snap_km` | 도로망 거리와 대표점·접점 연결거리(km) |
| `road_distance_primary` | 주 지표 사용 가능 여부(Y/N); N은 품질유보 |
| `route_quality`, `routing_category` | 도로거리 품질과 경로 대상 분류 |
| `origin_variant`, `outlet_pool` | 대표점 유형과 적용한 접점 집합 |

3km 초과는 반올림 전 거리로 판정한다. 5km 초과는 P1, 3km 초과·5km 이하는 P2다.
243곳 중 주 지표는 240곳, 품질유보는 3곳이다. 3km 초과 55곳 중 품질유보 1곳을 제외한
54곳을 경로 대상으로 쓴다. 대표점 거리는 주민 개인의 이동거리나 수혜인구 추정치가 아니다.

### 접점: outlets_validated.csv

| 컬럼 | 의미 |
|---|---|
| `outlet_id`, `type`, `name` | 접점 ID·기관 유형·지점명 |
| `addr`, `lat`, `lon` | 공개 주소·위도·경도 |
| `finance_open`, `finance_status`, `status_basis` | 분석 포함 프록시·상태·판단 근거. 실제 영업 확인과 구별 |
| `expansion_group`, `source`, `source_url` | 원래 목록/추가 집합 구분·출처·공식 조회 주소 |
| `source_snapshot`, `retrieved_at`, `baseline_date_status` | 스냅샷·조회시점·과거 기준일 존재 여부 확인 상태 |

빈 칸은 미확인 또는 원천에 해당 필드가 없는 경우이며 0이나 영업 중단으로 대체하지 않는다.
추가 전북 농·축협 334곳 중 업무 표시가 빈 271곳은 별도 민감도 분석 대상으로도 확인한다.
좌표가 가까운 서로 다른 지점을 임의로 하나로 합치지 않는다.

### 비교 결과: comparison_summary.csv

`method`는 경로 계산 방법, `allocation`은 시군별 운영일 배정 방식,
`max_stops`는 하루 최대 방문 수다. `covered`·`unvisited`는 행정동 대상 수,
`travel_km`는 모형 이동거리(km), `violations`는 경로 제약 위반 수다.
실행시간 컬럼은 해당 실행의 측정값으로 일반적인 속도 우위를 뜻하지 않는다.

## 3. 샘플과 전체 데이터

[current/](current/)의 두 CSV는 현재 입력에서 헤더와 앞 20행을 그대로 복사했다.
접점 샘플은 전체 목록 기준으로, 분석 조건으로 먼저 필터링한 표본이 아니다.
기본 검증은 샘플이 아닌 위 전체 파일을 읽는다.

기존 루트 `*.sample.csv`와 `source_manifest.json`은 8월 자료다.
과거 원천 9종, 수집·정제 규칙, 파일별 행 수와 라이선스는
[8월 자료 상세 기록](../docs/DATASETS.md)에 보존했다.

대용량 PBF·행정동 경계·그래프 캐시와 과거 원본은 저장소에서 제외했다.
업무 표시 검증에 필요한 일부 공식 HTML 스냅샷은 보완 분석 폴더에 포함한다.
원천 재구축은 정확한 버전의 자료를 따로 확보해야 하며, 현재 웹에서 다시 조회한 값이
저장된 스냅샷과 같다고 가정하지 않는다. 실행 방법은 [실행환경 설명서](../docs/실행환경설명서.md)를 따른다.
