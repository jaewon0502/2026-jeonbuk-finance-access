# 실행환경 설명서

팀명: 금방(금융 방방곡곡)

분야: 현안 해결 구현 · 문서 갱신일: 2026-10-17

## 1. 실행 환경과 확인 범위

| 항목 | 내용 |
|---|---|
| 언어·도구 | Python 3.11 이상, Node.js 20 이상, Bash; Git은 clone할 때 사용 |
| 이번 검증 환경 | macOS 27.0.1 arm64, Python 3.14.6, Node.js 26.4.0 |
| Windows | WSL2에서 아래 Bash 명령 사용; 이번 Windows·Linux 실기기 검증은 수행하지 않음 |
| 라이브러리 | 기본: 루트 requirements.txt; 원본 공간분석 재구축: analysis/theory_validation/requirements.txt |
| 네트워크 | 다운로드·최초 설치에 필요. 설치 후 제출 검증·화면 열람은 오프라인 가능 |
| API 키 | 제출 검증과 화면 열람에는 불필요 |
| 디스크 | 추적 파일 약 40MB. Git 이력·가상환경·별도 원본 데이터 공간은 추가 필요 |

기본 검증은 저장된 입력과 경로행렬로 결과를 재계산하고 무결성을 확인한다.
원천 API 재수집, 도로망 전체 재구축, 실제 차량 운행 검증은 포함하지 않는다.
현재 결과는 분석 접점 1,347곳, 경로 대상 54곳, 기본 방문 50곳이다.
8월 가공 자료와 군집분석은 과거 결과로 구분해 함께 보관한다.

## 2. GitHub 다운로드와 설치

저장소: https://github.com/jaewon0502/2026-jeonbuk-finance-access

macOS/Linux 또는 Windows WSL2 터미널에서 다음 명령을 실행한다.

```bash
git clone https://github.com/jaewon0502/2026-jeonbuk-finance-access.git
cd 2026-jeonbuk-finance-access
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
node --version
```

Node.js 출력이 v20 이상인지 확인한다. 이미 저장소를 받았거나 GitHub의
Code → Download ZIP을 사용했다면 앞의 두 줄 대신 받은 폴더로 이동한다.
새 터미널을 열면 저장소 루트에서 가상환경을 다시 활성화한다.

기본 requirements.txt에는 osmium 4.3.1, NumPy 2.4.6, SciPy 1.17.1이 고정되어 있다.
osmium은 원본 OSM 재구축용이며, Node.js 테스트는 내장 node:test만 사용한다.
pip는 각 패키지의 하위 의존성도 함께 설치한다.

## 3. 실행 순서와 정상 결과

### 3-1. 제출 검증

```bash
bash verify_offline.sh
```

마지막 줄이 PASS (offline)이고 종료 코드가 0이면 정상이다. 검증 과정에서
일부 가공 결과·리포트·대시보드 번들을 다시 쓰므로 작업 중인 결과가 있다면
별도 체크아웃에서 실행한다.

| 단계 | 확인하는 내용 |
|---|---|
| 1 | src/ Python 문법 |
| 2 | 경로 엔진·유형화·대시보드 Python 테스트 |
| 3 | 과거 유형·순회·민감도 결과와 현재 대시보드 번들 재생성, JavaScript 테스트 |
| 4 | 가공 자료 무결성, 금융업무 민감도 9개 결과 재계산, 공식 조회 근거 대조 |
| 5 | 공유 CSV 행 수·JSON 형식·화면 파일 존재 |

### 3-2. 대시보드 열람

docs/demo-jeonbuk/index.html을 브라우저로 직접 열거나 다음 서버를 사용한다.

```bash
python3 -m http.server 8000 --bind 127.0.0.1 --directory docs
```

브라우저 주소는 http://127.0.0.1:8000/demo-jeonbuk/ 이다. 종료는 Ctrl+C다.
지도와 글꼴을 함께 읽을 수 있도록 docs/ 전체를 유지한다. 운영조건을 바꾸면
선택한 시군의 경로와 운영일 배정을 브라우저에서 다시 계산한다.
방법론 설명은 docs/demo-jeonbuk/methodology.html에 있다.

### 3-3. 현재 자료의 개별 재검증

```bash
python3 src/build_dashboard_data.py
python3 analysis/feedback_validation/compare_sensitivity.py --check
python3 analysis/feedback_validation/verify_evidence.py
```

현재 경로 비교를 별도 폴더에 다시 생성하는 예시는 다음과 같다.
저장된 최종 결과를 덮어쓰지 않도록 result/reproduced/를 출력 경로로 쓴다.

```bash
python3 analysis/theory_validation/comparison/run_comparison.py \
  --input analysis/theory_validation/spatial/route_inputs/jeonbuk_route_scenario.json \
  --output result/reproduced \
  --label current_submission_replay
```

실행시간·실행 커밋·label은 원본 기록과 달라질 수 있다. 방문 대상·거리·제약 위반을
비교한다. result/reproduced/는 실행 후 생기는 검토용 결과이며 제출된 원본이 아니다.

### 3-4. 원본 재수집·공간분석 재구축 (선택)

```bash
python3 -m pip install -r analysis/theory_validation/requirements.txt
```

기본 패키지 외에 Shapely 2.2.0, pyproj 3.8.0, Requests 2.34.2를 사용한다.
실행 순서는 analysis/theory_validation/README.md와 하위 spatial/README.md를 따른다.
공통 OSM PBF와 행정동 경계 원본을 별도로 확보하고 input_manifest.json의 해시와
대조해야 한다. 라이브러리 설치만으로 원본이 복원되지는 않는다.

verify.sh는 원본 파일과 외부 API 연결을 확인하는 개발용 경로다. ECOS뿐 아니라
공공데이터포털·카카오 연결 조건도 있으므로 기본 제출 검증 명령으로 사용하지 않는다.
verify_source_lineage.sh 역시 별도 원본이 있는 환경 전용이며 이번 검증 대상에서 제외한다.

## 4. 데이터 경로와 파일명

모든 예시 명령은 저장소 루트에서 실행한다. 아래 경로는 저장소 기준 상대경로다.

| 경로 | 내용 |
|---|---|
| analysis/theory_validation/spatial/route_inputs/ | 현재 접점 목록 1,385행, 행정동 243행, 경로 후보·저장 행렬 |
| analysis/theory_validation/comparison/final_expanded_input/ | 현재 방법·조건별 비교 결과와 보고서 근거 |
| analysis/feedback_validation/ | 금융업무 표시 민감도 결과·공식 조회 근거 |
| data/processed/ | 과거 8월 기준 가공 자료 28개 |
| data_sample/current/ | 현재 접근성·접점 CSV의 상위 20행 미리보기 |
| data_sample/데이터_설명서.md | 주요 컬럼·단위·선별 조건·원천 문서 연결 |
| result/README.md | 현재 결과 원본과 과거 결과 사본의 위치 |

data/raw/와 보완 분석의 대용량 PBF·경계·그래프 캐시는 포함하지 않는다.
8월 원천 기록은 data/source_manifest.json, 현재 도로망·경계 기록은
analysis/theory_validation/inputs/input_manifest.json을 따른다.
원본 8월 PBF는 확보되지 않았으므로 과거 도로망 전체 재구축을 보장하지 않는다.

## 5. 자주 걸리는 문제

| 증상 | 조치 |
|---|---|
| node: command not found | Node.js 20 이상 설치 후 새 터미널에서 버전 확인 |
| numpy 또는 scipy를 찾지 못함 | 가상환경 활성화 후 requirements.txt 재설치 |
| osmium 설치 실패 | 기본 검증에 한해 NumPy 2.4.6·SciPy 1.17.1만 설치 가능; 도로망 재구축에는 osmium 필요 |
| shapely 또는 pyproj를 찾지 못함 | 원본 공간분석 경로라면 보완 분석 requirements.txt 설치 |
| Windows에서 .sh 실행 불가 | WSL2에서 설치·실행 과정을 진행 |
| 글꼴·지도 파일 404 | 서버 루트를 docs/로 지정하고 저장소 전체 다운로드 여부 확인 |
| 원천 해시 또는 파일 없음 오류 | 해당 버전의 원본을 확보하고 매니페스트와 대조; 검사를 생략하지 않음 |

## 6. 검증 기록과 한계

2026-10-17에 기준 커밋 346b362의 추적 파일만 있는 별도 체크아웃과 새 가상환경에서
루트 requirements.txt를 설치하고 bash verify_offline.sh를 실행했다.
실행 명령·환경·종료 코드·전체 출력은 docs/verify_offline_log.txt에 기록한다.

검증은 저장 결과의 계산 일치와 코드 동작을 확인한다. 추가 접점의 실제 영업 여부,
장소 사용승인, 실제 차고지·교통·운행 효과는 확인하지 않는다.
대시보드의 operational_ready=false와 분석 한계를 유지한다.
